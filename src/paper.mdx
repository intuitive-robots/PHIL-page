<section id="abstract" className="section-shell section-divider text-section" aria-labelledby="abstract-title">
  <div><p className="eyebrow">The idea</p><h2 id="abstract-title">A preview changes<br />{" "}when we intervene.</h2></div>
  <div className="body-copy">
    <p>Proactive Human-in-the-Loop (PHIL) is a framework for proactive policy correction and preference-based post-training. It lets an operator preview policy-predicted future motion in extended reality (XR) and intervene before an anticipated undesirable action.</p>
    <p>During takeover, the policy continues predicting trajectories from the robot’s current state. PHIL pairs rejected predictions with the corrective action chunks subsequently executed from the same physical state over the same horizon. Preference-based post-training encourages the policy to favor these corrections.</p>
    <p>Evaluated on real-world manipulation with a diffusion policy and a pretrained vision-language-action policy, PHIL improves mean success rates over HG-DAgger using five correction episodes per condition. A separate analysis finds fewer unnecessary recovery behaviors in successful episodes for policies trained with proactive corrections.</p>
  </div>
</section>

<section id="method" className="section-shell section-divider" aria-labelledby="method-title">
  <div className="section-heading"><p className="eyebrow">How PHIL works</p><h2 id="method-title">See ahead. Step in. Learn a preference.</h2><p>Turn human intervention into a comparison between what the policy proposed and what the robot should do.</p></div>
  <ResearchFigure src={overview} full="figures/overview.png" label="PHIL framework overview" alt="PHIL pipeline: initialize a base policy from demonstrations, preview future actions in XR and collect rejected–corrected action pairs, then post-train with imitation and preference objectives.">
    <strong>The PHIL framework.</strong> Base demonstrations initialize the policy. Proactive correction provides context-aligned preference pairs for post-training.
  </ResearchFigure>
  <ol className="method-steps">
    <li><span className="step-number">01</span><h3>Preview</h3><p>Render predicted end-effector trajectories in the physical workspace, so the operator can inspect upcoming motion.</p></li>
    <li><span className="step-number">02</span><h3>Correct</h3><p>Take control before an anticipated error. Policy queries and XR previews continue on the same fixed schedule.</p></li>
    <li><span className="step-number">03</span><h3>Pair</h3><p>Match a rejected prediction with the next executed action chunk, starting at the same query state and spanning the same horizon.</p></li>
    <li><span className="step-number">04</span><h3>Post-train</h3><p>Combine imitation on the original demonstrations with a preference objective that favors the corrective continuation.</p></li>
  </ol>
  <details className="method-detail"><summary>A closer look at preference pairs</summary><div className="body-copy"><p>The positive chunk contains the next <em>H</em> executed actions and may extend beyond the end of human takeover. The prediction accepted at release is excluded from negative samples. Only complete pairs are used for training.</p><p>In the experiments, actions run at 20 Hz with a 30-step prediction horizon and a query every 10 control steps. Both action chunks share the same context; the preference loss encourages a lower native imitation loss for the corrective chunk.</p></div></details>
  <div className="workspace-block"><div><p className="eyebrow">In the workspace</p><h3>Human guidance,<br />{" "}in context.</h3><p>A Meta Quest 3 interface aligns the predicted trajectories with the real robot. Holding the controller trigger enables correction; releasing it returns control to the policy.</p></div><ResearchFigure src={workspace} full="figures/workspace.png" label="Proactive correction in the physical workspace" alt="Sequence of XR views showing trajectory inspection, human takeover, continued policy previews during correction, and return to policy control.">A proactive correction sequence with synchronized robot and trajectory visualization.</ResearchFigure></div>
</section>
